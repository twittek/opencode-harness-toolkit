# Composable Project Dimensions

The interview does not classify a project into one exclusive scenario.

Real projects combine multiple characteristics. Model these as independent dimensions in the belief state.

## Core dimensions

```text
project.intent
project.delivery-stage
project.domain
project.user-groups
architecture.shape
architecture.frontend
architecture.backend
architecture.data
runtime.deployment
security.authentication
security.authorization
security.data-sensitivity
integrations.repository
integrations.work-tracking
integrations.documentation
integrations.external-systems
agent.responsibilities
agent.autonomy
agent.forbidden-actions
quality.gates
quality.verification
documentation.outputs
```

Topic packs may add dimensions without changing the engine.

## Optional descriptive tags

Tags such as these may summarize the final state but must not drive a fixed question tree:

```text
frontend
backend
fullstack
monorepo
library
developer-tooling
production
prototype
migration
regulated
integration-heavy
data-ai
documentation-only
```

Several tags may apply simultaneously.

## Rule

Use dimensions to calculate uncertainty and generate the harness. Use tags only for explanation, search and analytics.
